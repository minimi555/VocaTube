# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

VocaTube is a vocabulary/video-learning app: a FastAPI backend serves word lookups, downloaded YouTube videos with bilingual subtitles, an English-test-prep RAG assistant, a QS-top-150 school search agent, and an LLM-powered quiz generator; a Jetpack Compose Android app (`frontend/`) consumes it. The backend never runs the YouTube downloader itself — that pipeline was removed from the repo.

## Setup and commands

Backend dependency management uses `pip` (see `backend/requirements.txt`, requires Python >=3.12). There is no test suite or lint config in the repo.

Run the API server (from `backend/app/`, so relative imports like `from database import ...` resolve):
```
cd backend/app && uvicorn main:app --host 0.0.0.0 --port 8000
```

Build/ingest the RAG vector store (must be run once before `/ask` works — it raises 503 otherwise):
```
cd backend/app && python RAG.py ingest
```
`RAG.py` also has a CLI for ad-hoc querying outside the API: `python RAG.py ask "问题..."` or `python RAG.py` for an interactive REPL.

Run the school-search agent standalone (bypassing the API), useful for debugging Tavily/DeepSeek behavior directly:
```
cd backend/app && python school_searcher.py
```

Frontend (Android Studio project under `frontend/`):
```
cd frontend && ./gradlew assembleDebug
```
When testing against a locally-running backend over USB: `adb reverse tcp:8000 tcp:8000` (the app's `Network.BASE_URL` is hardcoded to `http://127.0.0.1:8000/`).

### Required `.env` (in `backend/.env`, gitignored)
- `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME_MAIN` (wordbase), `DB_NAME_LOG` (videobase) — MySQL connection, read by `database.py` via `pydantic_settings`.
- `TAVILY_API_KEY`, `DEEPSEEK_API_KEY` — school search agent (`school_searcher.py`) and quiz agent (`quiz_agent.py`).
- `ZHIPU_URL`, `ZHIPU_API_KEY` — RAG embeddings (`RAG.py`).

## Architecture

### Backend (`backend/app/`, FastAPI)

**Two logically separate MySQL databases**, each with its own SQLAlchemy engine/session/declarative base (`database.py`: `wordbase_engine`/`WordbaseSessionLocal`/`WordbaseBase` and `videobase_engine`/`VideobaseSessionLocal`/`VideobaseBase`, exposed as FastAPI dependencies `get_wordbase_db`/`get_videobase_db`). Models for both live together in `models.py` but inherit from different bases:
- **wordbase** (`DB_NAME_MAIN`): `Word`/`Translation`/`Category`/`WordCategory` (vocabulary + many-to-many category tagging), plus `School`/`SchoolSearchHistory` for the school-search feature.
- **videobase** (`DB_NAME_LOG`, despite the name it stores video metadata, not logs): `Video` — title + relative paths to video/zh-subtitle/en-subtitle files. These paths are served as static files: `main.py` mounts `/opt/assets` at `/assets`, and `GET /videos/{id}` builds URLs as `/assets/video/{video_path}`, `/assets/subs/zh/{subtitle_path_zh}`, `/assets/subs/en/{subtitle_path_en}`.

Neither DB is populated by code in this repo — the videos+subtitles referenced by `videobase` are expected to already exist under `/opt/assets/...` on the host.

**RAG test-prep assistant** (`RAG.py`, backs `POST /ask`): ingests `backend/app/english_learning_md/*.md` (CET4/CET6/IELTS/SAT/TOEFL/kaoyan prep notes) by splitting on markdown headers then capping chunk size, embeds via a hand-rolled `ZhipuEmbeddings` (HTTP call to Zhipu's `embedding-3`, not a LangChain-provided integration), and stores in a Chroma collection persisted to `backend/app/chroma_db/` (gitignored, must be rebuilt locally with `python RAG.py ingest`). Answers are generated by DeepSeek (`deepseek-v4-flash` via `langchain-deepseek`) grounded strictly to the top-k retrieved chunks. `main.py`'s `/ask` endpoint translates the "vector store not built" `RuntimeError` into an HTTP 503.

**QS school-search agent** (`school_searcher.py` + `backend/QS.py`, backs `POST /school/search` and `GET /schools`): a LangChain `create_agent` (DeepSeek + `TavilySearch`) restricted via `include_domains=QS_150_list` to the official domains of QS-top-150 universities (`QS.py`'s `QS_150_schools` — rank/name/domain triples; `QS_150_list` is the flat domain list Tavily/the `schools` DB table uses). This agent is slow (10-30s per query) — don't assume synchronous-fast latency when touching this path. Every `/school/search` call is persisted to `SchoolSearchHistory` (wordbase).

**Quiz agent** (`quiz_agent.py` + `quiz_prompts.py` + `quiz_schemas.py`, backs `POST /quiz/generate` and `POST /quiz/grade`): a LangGraph `StateGraph` with three stages:
1. `prepare_words` — parses an `.srt` subtitle file via `utils/parse.py`, lemmatizes with spaCy (`utils/lemma.py`), and cross-references against a word category (e.g. CET4) in the DB to find target vocabulary.
2. `generate_quiz` — LLM call (DeepSeek `deepseek-v4-pro`) to produce 10 cloze blanks + 2 reading comprehension questions from the subtitle text.
3. `review_quiz` — deterministic structure validation (`_script_validate`) + LLM quality review; loops back to `generate_quiz` on failure, caps at 2 review rounds.

Generated quizzes are held in an **in-memory store** (`_quiz_store`, 1-hour TTL keyed by UUID). `POST /quiz/generate` returns the quiz_id + questions (without answers); `POST /quiz/grade` looks up the stored answers, compares, and calls the LLM for wrong-answer explanations. This means quizzes do not survive server restarts. The generate endpoint is slow (30-60s due to the LLM review loop) — the frontend sets a 120s read timeout via `X-Read-Timeout`.

**Utility modules** under `backend/app/utils/`:
- `parse.py` — `_parse_srt()` strips SRT timing/index lines, returns plain text.
- `lemma.py` — `_get_lemma()` runs spaCy `en_core_web_sm` lemmatization, filtering stop words and audience-noise tokens (applause, laughter, etc.).

### Frontend (`frontend/`, Jetpack Compose Android app)

MVVM: `ui/<feature>/{FeatureScreen,FeatureViewModel}.kt` per bottom-nav section, `data/remote/` for the Retrofit layer, `data/local/` for on-device persistence. Four sections wired through `ui/nav/Section.kt` (`Dictionary`, `VideoLearn`, `Wordbook`, `Consult`).

- `data/remote/Network.kt` builds the single Retrofit/OkHttp client; `ApiService.kt` mirrors the FastAPI endpoints 1:1. A custom `X-Read-Timeout` header + OkHttp interceptor lets a single call override the default read timeout — set this header rather than a global timeout when adding another slow endpoint.
- `Network.assetUrl()` must be used to turn backend-relative `/assets/...` paths into loadable URLs — it per-segment URL-encodes (paths contain spaces and full-width Unicode from video titles) while preserving `/` separators.
- The backend is plain HTTP (`usesCleartextTraffic=true`), reachable only via `adb reverse` — there is no auth.
- `plan_frontend.md` (repo root) is a design doc for the VideoLearn quiz UI integration — check it for the intended ViewModel/state shape before restructuring that screen.
- `ui/videolearn/QuizSection.kt` contains the quiz UI composable (cloze fill-in-the-blank + reading comprehension).
- `data/subtitle/SrtParser.kt` and `Subtitles.kt` handle client-side SRT parsing for the video player.
- `tts/TtsManager.kt` wraps Android TTS for word pronunciation in the dictionary feature.
